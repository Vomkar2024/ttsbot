## 4. Failure Diagnostics

### Failure 1: `FormattedTTSMessage` Container Protocol Defect
- **Area**: Message Ingestion & Chat Intelligence (`src/tts/format_message.py`)
- **Verdict**: **FAIL**
- **Symptom**: Executing a Python membership test such as `'spoken_text' in formatted_msg` or `'cleaned_text' in formatted_msg` crashes with:
  ```
  TypeError: attribute name must be string, not 'int'
  ```
- **Steps to Reproduce**:
  ```python
  from src.tts.format_message import format_message_for_tts
  msg = format_message_for_tts({"content": "Hello", "author": {"name": "Alice"}})
  is_present = "spoken_text" in msg  # Crashes with TypeError
  ```
- **Observable Cause**: `FormattedTTSMessage` defines `__getitem__(self, item: str) -> Any: return getattr(self, item)`. However, it does not define `__contains__`. In Python, evaluating `key in obj` on an object that lacks `__contains__` falls back to integer sequence iteration (`obj[0]`, `obj[1]`, etc.). When Python passes integer `0` to `__getitem__`, `getattr(self, 0)` fails because attribute names must be strings.
- **Recommended Fix**: Add a `__contains__` method to `FormattedTTSMessage`:
  ```python
  def __contains__(self, key: str) -> bool:
      return hasattr(self, key)
  ```

## 5. Prioritized List of Failures & Recommendations

1. **High Priority: Fix `FormattedTTSMessage.__contains__` Protocol Defect**
   - **Why**: Any third-party integration, test, or handler checking dictionary-like properties with `"key" in msg` will raise an unhandled `TypeError` instead of evaluating cleanly.
   - **Fix**: Implement `def __contains__(self, key: str) -> bool: return hasattr(self, key)` in `src/tts/format_message.py`.

2. **Medium Priority: Set Connection/Socket Timeout for Online `gTTS` Requests**
   - **Why**: When running in an environment with partial or restricted network connectivity (e.g. firewalled host or offline container), `gTTS` uses standard `urllib3`/`requests` which can block on TCP handshakes.
   - **Fix**: Add a timeout (e.g., 5.0 seconds) to `gTTS.write_to_fp()` so that fallback to offline `eSpeak NG` occurs instantaneously without delaying queue processing.

3. **Low Priority: Guard `SerialQueue.enqueue()` Against Absent Event Loops**
   - **Why**: In `src/voice/serial_queue.py`, `_ensure_processing()` assumes an active event loop in the caller's thread. If invoked outside an async context, `get_event_loop()` raises a `RuntimeError` in Python 3.10+.
   - **Fix**: Add an internal check or fallback to schedule jobs on the bot's main loop if called from a worker thread.
