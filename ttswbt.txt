## 2. Detailed Findings: Broken, Partially Broken, and Suspicious Features

### Finding 1: `FormattedTTSMessage` Container Protocol Defect (`TypeError` on `in` check)
- **Status**: **BROKEN**
- **Location**: [`src/tts/format_message.py#L213-L215`](file:///e:/Download/Omkar/botmaker/tts/src/tts/format_message.py#L213-L215)
- **Source Code**:
  ```python
  class FormattedTTSMessage:
      ...
      def __getitem__(self, item: str) -> Any:
          return getattr(self, item)
  ```
- **Execution Path & Failure Cause**:
  `FormattedTTSMessage` implements `__getitem__` to support dictionary-style access (`msg["spoken_text"]`). However, it does not implement `__contains__`. In Python, executing a membership test (`"spoken_text" in formatted_msg`) on an object lacking `__contains__` triggers Python's fallback sequence protocol: Python attempts to iterate over integer indices `obj[0]`, `obj[1]`, etc.
  When integer `0` is passed to `__getitem__(self, item: str)`, `getattr(self, 0)` fails with:
  ```
  TypeError: attribute name must be string, not 'int'
  ```
- **Impact**: Any external consumer, middleware, test, or slash command helper checking whether a property exists on `FormattedTTSMessage` using standard Python dictionary idiom (`if "spoken_text" in msg:`) crashes immediately with an unhandled exception.
- **Verification Mode**: Static analysis and direct reproduction.
